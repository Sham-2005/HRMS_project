# Dayflow HRMS Dataset

## 1. Dataset Overview
*   **Dataset Name**: Dayflow HRMS Synthetic HR Dataset
*   **Source**: `backend/seed.py`
*   **Type**: Synthetic / Seeded HR data
*   **Purpose**: Development, testing, demonstration, and workflow validation
*   **Database**: SQLite (`dayflow.db`)
*   **Main HR Entities**: Users, Employees, Attendance Logs, Leave Requests, Payroll History, Notifications, and Audit Logs.

> [!NOTE]
> This dataset is synthetic data generated by the application's seed process. It does not represent real employees or confidential employee information.

---

## 2. Dataset Entities

The database schema represents the following core entities:

| Entity | Purpose | Example Information |
|---|---|---|
| **User** | Authentication and roles | Email, role (ADMIN, HR, EMPLOYEE), status |
| **Employee** | Employee profile | Employee ID, name, masked phone/address, designation, encrypted salary parameters |
| **Attendance** | Attendance tracking | Date, check-in, check-out, status (PRESENT, HALF_DAY, ABSENT, LEAVE), work hours |
| **Leave Request** | Leave management | Leave type (PAID, SICK, UNPAID), start/end dates, reason, status (PENDING, APPROVED, REJECTED) |
| **Payroll** | Salary management | Billing month, base salary, allowances, deductions, net salary, payment status, transaction ID |
| **Document** | Employee documents | Title, file path, document type (ID_PROOF, CONTRACT, DEGREE, OTHER) |
| **Notification** | Employee notifications | Title, message summary, read/unread status, timestamp |
| **Audit Log** | Security/activity tracking | Action, actor, timestamp, redacted details |

## 10. Data Flow

```
   seed.py
      ↓
 SQLite Database (dayflow.db)
      ↓
  FastAPI Backend API
      ↓
 Authentication / RBAC Guard (deps.py)
      ↓
  React Frontend Client
      ↓
 Admin / HR / Employee Dashboards
```

The seeded data is utilized across various modules:
*   **Admin/HR**: Views all employees, reads cumulative attendance/leave metrics, generates payslips, updates structures, and monitors audit logs.
*   **Employees**: Check-in/check-out, apply for leaves, download processed payslips, and modify personal contact profiles.

## 12. Data Security
*   **Password Protection**: Plaintext credentials are never saved. Passwords are encrypted using the `bcrypt` hashing algorithm (12 rounds).
*   **PII & Financial Encryption**: Sensitive employee values (`phone`, `address`, `base_salary`, `allowances`, `deductions`, `net_salary`) are transparently encrypted at the model decorator level using `AES-256-GCM` with a 256-bit key.
*   **Access Verification**: JWT signatures (`HS256`) restrict API calls, while role dependencies check permissions on the backend routes. Password parameters are omitted from responses.
